# About the Author

My name is Jon Leithe. I maintain Project Polaris Academy as a long-term
engineering notebook and learning companion.

## Academic Context

I am beginning a part-time, online Master of Science in Aerospace Engineering
at UiT Narvik in August 2026. Project Polaris Academy supports those studies by
bringing together course notes, worked examples, references, diagrams, and
educational software in one version-controlled knowledge base.

My current academic focus is Linear Algebra II. Over time, I expect the project
to expand into subjects including calculus, differential equations, mechanics,
orbital mechanics, control theory, signal processing, space systems, embedded
programming, and scientific computing.

## Professional Background

My professional experience includes:

- scientific infrastructure;
- very long baseline interferometry (VLBI);
- global navigation satellite systems (GNSS);
- hydrogen masers;
- Linux systems and automation;
- Python and C++;
- electronics and instrumentation.

This background shapes the project. I value explanations that connect theory
to physical systems, measurement, computation, and practical engineering.

## Development Environment

My primary development environment is:

- Arch Linux;
- `paru` for package management;
- VS Code as the primary editor;
- Kitty with herdr as the terminal emulator;
- Bash as the shell;
- Hyprland as the window manager.

The preferred software baselines are modern C++ (currently C++20), Python
3.13 or newer, and CMake where it is appropriate. Documentation is written in
portable Markdown and built with Quarto and XeLaTeX. Quarto uses Pandoc as its
document-conversion engine internally.

I use the Academy repository's navigable Quarto HTML output for local review
and cross-format validation. The separate `jonleithe.no` project owns the
public website's assembly, presentation, and deployment.

## Working Principles

I treat this repository as a real engineering project rather than a loose
collection of notes. My priorities are:

1. correctness over speed;
2. readability over cleverness;
3. maintainability over shortcuts;
4. reproducible builds;
5. automation where it provides lasting value;
6. small, focused changes with meaningful version history.

I prefer simple tools, minimal dependencies, and clear architecture. New
technology should solve a concrete problem rather than add complexity for its
own sake.

## Approach to Learning and Writing

I want the notes to explain why an idea works, not merely list procedures. A
good treatment should begin with intuition, introduce notation carefully, give
the formal mathematics, and reinforce it with worked examples and engineering
interpretation.

The material is written primarily for my own study and future reference. It
should nevertheless be clear enough to help another engineering student and
robust enough that I can trust it years later. The notes should reflect my own
understanding rather than reproduce textbook prose.

## Why Project Polaris Academy Exists

The project serves several related purposes:

- support my master's studies;
- build a durable personal engineering reference;
- strengthen my software engineering practice;
- connect academic theory with professional engineering experience.

The long-term aim is a knowledge base with the usefulness and consistency of a
professionally maintained technical handbook. Selected material may eventually
be published on [jonleithe.no](https://jonleithe.no), while the repository
itself remains first and foremost a personal learning resource.
